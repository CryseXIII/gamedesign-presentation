# Milestone: AVDump3 Setup

## Context
CT213 Shoko needed AniDB AV dump support after the user set a UDP API key in AniDB account settings.

## Decision
Install the AVDump3 bundle on CT213, add a stable wrapper command, and populate Shoko's `AniDb.AVDumpKey` from the live AniDB credential Shoko was already using.

## Rationale
Shoko already had valid AniDB login credentials. AVDump3 requires the AniDB auth pair to run, and the container only had .NET 8/10 installed, so roll-forward was the minimal path that avoided a separate runtime install.

## Challenges
- The AVDump3 bundle targets .NET 6.
- The container did not have a .NET 6 runtime installed.
- The API settings endpoint required an explicit `api-version=3.0` and JSON Patch payload.

## Implementation Notes
- Downloaded `avdump3_8293_stable.zip` into CT213 and extracted it under `/opt/avdump3`.
- Verified the Linux entrypoint works with `DOTNET_ROLL_FORWARD=Major`.
- Created `/usr/local/bin/avdump3` as a wrapper for the roll-forward launch.
- Patched live Shoko settings so `AniDb.AVDumpKey` is populated.

## Follow-Up
- Run an actual AVDump job on a known file to confirm AniDB accepts the credentials.
- If the user wants a different UDP API key than the one already stored in Shoko, replace the setting with that exact value.
